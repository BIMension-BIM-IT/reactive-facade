# IndoorGlare: 실내 눈부심(DGP) 시뮬레이션 (GlareSim과 분리, 10/15)

Grasshopper Glare 1/2/3(방사형 센서 → DGP 엔진 → 색칠)을 유니티로 옮겼어요.
태양·시각은 반응형 루버 컨트롤러(sun_louver.csv)를 쓰고, 루버는 화면에서 실제로 돌아간 날 각도를 읽어요.

**GlareSim(반사광) 폴더와 완전히 따로예요.**
- GlareSim 파일을 하나도 고치지 않고, GlareSim의 클래스도 쓰지 않아요.

  - 이름으로 찾아서 씬 상태를 읽기만 해요(GlareSim의 LouverSceneLink와 같은 방식).
  - 루버 쪽 읽기는 `IndoorLouverLink.cs` 한 파일에만 있어요.

## 붙이는 순서

1. IndoorGlare 폴더를 Assets에 넣어요.
2. 빈 오브젝트 "IndoorGlare"에 **IndoorGlareSim**을 붙여요. 연결 칸(Louver Controller, Louver Rig, Louver Root Override, Sun Override)은 비워 두면 자동으로 찾아요.
3. **유리 지정**(가장 중요):
   - Glass Roots에 유리 오브젝트(또는 Rhino 유리 레이어로 들어온 부모)를 넣어요.
   - 비워 두면 이름·부모 이름·재질 이름에 Glass Keywords(glass, 유리, glazing, window, 커튼월)가 들어간 메시를 유리로 봐요.
     - "외측 저반사유리"도 이 규칙으로 유리가 돼요.
   - 유리가 아닌 메시는 전부 빛을 막는 면이에요(벽·슬래브·기둥·가구·주변 건물·지면).
   - 루버 날은 자동으로 빠지고 따로 계산해요.
   - 모서리 "고정" 기둥은 날이 아니라 막는 면으로 들어가요.
4. **센서 영역**: 다음 중 하나로 정해요.
   - (권장) 편집 모드에서 IndoorGlareSim Inspector의 **"9층 영역 만들기"** 버튼을 눌러요.
     - 루버 날 범위로 그 층 바닥을 덮는 IndoorGlareZone이 생겨요. 층 번호는 Auto Floor 값이에요.
     - 크기·위치를 고쳐서 서우님 실내 같은 방 하나만 덮어도 돼요.
   - IndoorGlareZone을 직접 놓아도 돼요. 오브젝트 위치 = 바닥 한가운데, size = 가로 × 천장 높이 × 세로예요.
   - 영역이 하나도 없으면 재생할 때 Auto Floor 층 전체로 임시 영역을 만들어요(저장 안 됨).
5. 재생하고 Console을 확인해요.
   - `[Indoor] 루버 연결: … 반사광 GlareSim … | 날 17514장 …`
   - `[Indoor] 모델: 유리 메시 …개, 막는 메시 …개` → 유리가 0개면 3번을 다시 봐요.
   - `[Indoor] 센서 …개 (점 …개, 창이 안 보이는 점 …개), 날 상자 …개`와 영역별 유리 넓이(동/남/서/북 m²)
6. 패널은 Game 창 왼쪽 위(H 키), Scene 창 왼쪽(오른쪽은 반사광 패널), IndoorGlare Inspector 맨 위에 나와요.

## 패널

- **끔 / 현재 시각 / 하루 GA**
  - 현재 시각: 지금 화면의 해·루버로 센서마다 DGP를 계산해요. 웹·슬라이더로 시각이 바뀌면 따라가요.
  - 하루 GA: 컨트롤러 시각을 재실 시간(8~18시) 동안 10분씩 돌려서 GA를 계산해요.
    - GA = 재실 시각 중 DGP < 0.40인 비율이에요.
    - 끝나면 원래 날·시각으로 돌아가요.
    - "대표일 4일 모두"를 켜면 춘분·하지·추분·동지를 합쳐요.
- **반응형(내부 루버) / 반응형(외부 루버) / 모두 열림 / 루버 없음**: 반사광 패널과 같은 4가지예요.
  - 내부 루버: 날 바깥에 외측 유리가 있어요. 창으로 들어오는 빛에 Outer Glass Visible Transmittance(기본 0.85, 임의의 값)를 한 번 더 곱해요.
  - 외부 루버: 같은 날 각도, 외측 유리 없음.
  - 모두 열림·루버 없음: 외측 유리 없이 계산해요(반사광과 같아요).
  - 실내 눈부심은 화면의 외측 유리·루버를 켜고 끄지 않아요. 화면 표시는 반사광 패널이 맡아요.
  - 4가지 비교 버튼은 하루 GA를 네 경우로 한 번에 계산해요.
- **맑음 / 구름 조금 / 흐림 / EPW**: 하늘 밝기를 정해요.
  - 맑음·구름 조금·흐림은 IES 하늘 모델이에요. 맑음 기준 고도 60°에서 직달 약 97 klx, 확산 약 15 klx예요.
  - EPW는 StreamingAssets에 EPW 파일을 넣고 Epw File Name을 적어요. 그 대표일 날짜·시각의 행을 써요.
- **표시 값(하루)**: GA % / 글레어 시간 / 최대 DGP
- **색**: Glare3와 같은 팔레트예요.
  - DGP: 초록 → 빨강. 0.35 인지 가능, 0.40 방해, 0.45 견디기 어려움.
  - GA: 빨강 → 초록. 빨강일수록 글레어가 잦아요.
  - 회색 쐐기 = 창 밖이 안 보이는 센서(코어 안 등).
- **벽 뒤에서도 보기**: 센서 쐐기가 슬래브·벽에 가려도 보이게 해요.
- **카메라 시점 DGP**: Main Camera(또는 View Camera) 위치·방향의 DGP를 Game 창 아래에 계속 보여줘요.
  - 날 상자는 센서 영역 층 ±1층에만 있으니 그 층 안에서 쓰세요.
- **다시 준비**: 영역을 옮기거나 모델을 바꾼 뒤 눌러요.
- **CSV 저장**: 프로젝트 폴더/GlareResults/glare_indoor_….csv에 저장해요.
  - 내용: 센서마다 위치, 방향, 창 보임, DGP, 눈 조도, GA, 글레어 시간, 최대 DGP
  - 좌표는 Unity 좌표(m)예요.
- 웹에서 부를 함수:
  - `SetMode("off"|"instant"|"daily")`
  - `SetLouverCase("inner"|"outer"|"open"|"none")`
  - `SetSky("clear"|"partly"|"overcast"|"epw")`
  - `Recompute()`, `Rebuild()`, `RunCompare()`
  - 결과 JSON은 On Result Json 이벤트와 Last Result Json 칸으로 나와요.

## 반사광(GlareSim)과 같이 쓸 때

두 시뮬레이션 모두 하루 계산 때 컨트롤러 시각을 돌려요. 그래서 실내 쪽이 이름으로 반사광 상태(`GlareReflectionSim.IsBusy`)를 보고 맞춰요.

- 반사광이 계산 중이면 실내 하루 계산은 시작하지 않고 기다려요. 실내 현재 시각 계산도 쉬어요.
- 실내 하루 계산 중에 반사광 하루 누적이 시작되면, 실내 계산은 멈춰요. 반사광이 끝나면 원래 날·시각으로 되돌리고 다시 계산해요.
- 실내 하루 계산 중에 웹이나 사용자가 날짜·시각을 바꾸면, 그 시각을 지키고 멈춰요. '다시 계산'으로 다시 해요.
- 실내 하루 계산 중에 반사광이 "현재 시각" 모드면, 반사광도 시각마다 다시 계산해서 느려져요. 그동안 반사광을 "끔"으로 두면 빨라요.

## 계산 방식

1. **준비(한 번)**: 점마다 천공 표본 1,160방향(Sky Resolution 2)으로 광선을 쏴요.
   - 유리를 지나 밖이 보이는 방향만 남겨요.
   - 그 방향이 지나는 유리 앞의 날(어느 입면, 어느 날)을 기억해요.
   - Glare2와 같은 규칙: 유리를 지나기 전에 막히면 안 보임, 유리와 5 cm 안에 붙은 벽은 무시해요.
   - Glare2와 다른 점: 유리를 지난 뒤 다른 면에 닿으면 무조건 검게 보지 않아요.
     - 아래로 가다 수평면에 닿으면 지면 밝기로 봐요.
     - 주변 건물 벽에 닿으면 그 벽 밝기(Context Reflectance)로 봐요.
2. **시각마다**:
   - 하늘: 컨트롤러가 돌린 해(Directional Light) 방향으로 하늘·지면 휘도를 만들어요(Glare2와 같은 식).
   - 루버(하늘·지면): 날 사이를 통과하는 비율 = 1 − 폭·|sin(θ−φ)| / (간격·|cos φ|)
     - θ = 그 날의 실제 각도, φ = 그 방향이 입면과 이루는 평면각
     - 반사광 쪽 LouverArray2D와 같은 값이에요(차이 0.0005).
     - 날이 가린 부분은 날 표면 밝기(Blade Reflectance)로 채워요.
   - 루버(해): 점마다 실제 날 위치·각도의 얇은 상자에 광선을 쏴서 해가 보이는지 안 보이는지로 정해요.
   - 날이 있는지: LouverRig.userHidden으로 판단해요(반사광과 같은 규칙).
     - LouverPerformance가 카메라 반대쪽 면을 꺼도 날이 있다고 봐요.
     - 날 범위도 메시로 구해서, 꺼진 날도 위치가 맞아요.
   - 상호반사: Glare2와 같은 적분구 근사예요.
     - 유리 넓이는 영역 안의 유리를 입면별로 10 cm 칸에 칠해서 재요. 안쪽 유리와 외측 유리, 앞뒷면이 겹쳐도 한 번만 세요.
   - DGP = 5.87e-5·Ev + 0.092·log10(1 + Σ L²·ω·통과율/(Ev^1.87·P²)) + 0.159
     - 2,000 cd/m² 이상 패치와 해 원반이 광원이에요(Glare2와 같아요).
3. **하루 GA**: 재실 시간 10분마다 DGP를 구해서 기준(0.40) 미만인 비율이에요. 해가 없는 시각은 글레어 없음으로 세요(Glare2와 같아요).

## 느릴 때

- **준비 시간** ≈ 점 수 × 1,160 광선이에요.
  - 층 전체 자동 영역은 1.5 m 간격이라 점 약 1,200개, 수십 초 걸릴 수 있어요.
  - 방 하나만 덮게 영역을 줄이거나, Grid Size를 키우거나, Sky Resolution을 1로 낮춰요.
- **하루 GA**: 시각 60개 × (한 프레임 + 계산)이에요. 4일·4가지 비교는 몇 분 걸릴 수 있어요. 진행률이 패널에 떠요.
- WebGL에서는 한 스레드라 더 느려요. 무거운 계산은 에디터에서 하고 CSV·JSON으로 넘기는 걸 권해요.

## 계산에서 빠진 것

- **시간**: 대표일 4일만 있어요(루버 CSV가 대표일 기준). 1년 GA는 루버 CSV가 날짜별로 있어야 해요.
- **하늘**: 기본은 맑은 하늘이라 실제 날씨 평균보다 글레어가 많게 나와요.
- **유리**: 투과율이 입사각에 따라 줄어드는 효과를 무시해요(Glare2와 같아요).
  - 외측 유리도 투과율 한 값만 곱하고, 외측 유리에 비친 반사상은 빼요.
- **상호반사**: 방 안 조도를 고르게 보는 근사예요(Glare2와 같아요).
- **날 밝기**: 날 표면·주변 건물 벽 밝기는 해를 뺀 연직 확산 조도 × 반사율의 근사예요.
- **날 모양**: 위아래로 긴 판으로 봐요. 층 사이 틈은 하늘 쪽에서 무시해요.
- **입면 방향**: 정확히 동서남북을 본다고 가정해요(루버 로직과 같아요).
- 최종 판단은 Radiance(Honeybee) 결과로 확인하세요.
